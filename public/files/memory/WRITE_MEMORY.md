# WRITE_MEMORY.md — 如何写记忆

## 目录结构

```
~/memory/
  IDENTITY.md          # 你是谁。你的身份认知。自动注入。
  USER.md              # 关于用户。偏好、技术栈、项目、约束、困境、态度。自动注入。
  MEMORY.md            # 长期记忆规范。自动注入。
  WRITE_MEMORY.md      # 如何写入记忆。这份文件。
  root/
    some.md            # 记忆文件
```

该目录可能只读，查 VFS 列表看状态。

按需在 root 创建子目录和文件。文件名就是 key——用人能看懂的名字，用户在你身边。

## 格式

记忆是在开头嵌入 frontmatter 的 Markdown 文件，格式如下：
```markdown
---
tags: 空格 分隔 标签 时间戳 2026-10-01 一句话介绍
---
记忆正文（Markdown）
```

文件名可以长点，
写适合且多的标签，用你的想法，你自认为搜索时用得到的关键词和相关文件名，不是给人看，是你自己查。

用 **Append** 和 **Edit**。按需附加时间，这样就能知道用户去年喜欢 Vue 今年换 React 了。（也别忘了处理过时或矛盾的 facts）
明确知道要整体重写一个文件再用 Write。大多数时候你是在追加新事实，不是覆盖。

## 维护

root 文件夹里的 md 的 tags 会被解析并注入系统提示。

适时删除过时的链接。你如果注意到某个文件很久没人动了，可以提醒用户。
你不一定有时间感，所以 root 下超过 100 个文档时会提示：我们至少还有定期维护

这不代表你只能记住 100 个文件，还有子目录。你可以维护二级索引，比较麻烦，因为这开始超出本系统的范围了

全局记忆不应该写成超链接（直接内联文本），用户对你的要求也不该写入索引（该写进 IDENTITY）。
短期记忆*建议*写在对应工作区的 MEMORY.md 里，然后在 AGENTS.md 里引用它（修改 AGENTS.md 那一刻会破坏缓存）

## 存什么

**该存的**：跨对话有用的稳定事实。偏好、技术栈、在做的事、反复出现的约束、用户的态度和困境、你做过的决策和原因。

**不该存的**：ID 号码、电话号码、access token、私钥、密码。这些是硬约束。不是「尽量不要存」，是「不要存」。
