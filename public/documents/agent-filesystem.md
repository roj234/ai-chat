# Agent 与文件系统

AiChat 具有文件访问能力，支持文件系统操作，并通过后端实现命令执行。  
除了后端，文件系统接口支持OPFS，虚拟文件系统，以及（不支持火狐的）showFilePicker API  
单纯操作文件并不需要后端

## 启用文件系统访问

- 模型在有需要时调用 `Use` 工具启用 `Files` 工具组
- 或用 Agent 按钮打开工具配置激活
- 或自行构造工具调用

## 注意事项

前后端的 Glob / Grep 实现并非完全统一，且有部分特殊规则：
- 读取项目根目录的 `.ignore` 或 `.gitignore`，前者优先级更高
- 匹配的文件会像 ripgrep 一样被忽略
- 忽略 `.` 开头的隐藏文件，但 RunJS 的 `fs.list` 不会忽略（传入 showHidden = true）
- 特殊规则：这些文件只读（无法防止命令），RunJS 沙箱也无法写入
- 特殊规则：若一个忽略路径以 `/` 结尾，那么它会在 Glob 中显示，但省略子目录

后端支持环境变量或【bin 文件夹中(仅windows)】的rg ([ripgrep](https://github.com/BurntSushi/ripgrep))  
使用ripgrep的好处：**快**  
使用ripgrep的坏处：
- 每次调用都搜索整个路径，无法因文件数量足够而 early exit
- 不支持上述【省略子目录】规则
- 部分情况下AI提供了一些不支持的正则表达式，JS引擎会报错，而rg可能执行并报告没有匹配

## 安全

**命令执行没有沙盒**。如果允许，它可以在服务器上执行任意命令。  
不过，它只在[专用文件服务](./build.md#部署)中开启。

- 你应该使用 Docker 等容器技术隔离环境
- 或审查模型的命令执行请求（默认需要确认每一条命令）
- 好消息：自动沙箱模块正在开发中！

# 完全编辑模式

[设计理念](./philosophy.md#完全编辑模式)

### 如何使用

在消息上点击编辑按钮，即可修改对应内容。后续对话将基于修改后的内容继续。  
保存按钮的右侧是“追加工具调用”和“插入思考内容”按钮。  
每个工具调用通过点击展开，在修改后需要点击它们的保存按钮。  
如果 Schema 验证和点击按钮搞得你很烦躁，你甚至可以通过 `设置 > 数据管理 > 编辑当前对话的原始数据` 编辑 (数据无价，小心使用)
