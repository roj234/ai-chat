# Agent 与文件系统

AiChat 具有虚拟文件系统接口，并通过可选的文件后端实现真机命令执行。  
除了后端，还支持OPFS，（不支持火狐的）showFilePicker API 和插件的虚拟化文件系统等
单纯操作文件并不需要后端

## 启用文件系统访问

- 模型在有需要时调用 `Use` 工具启用 `Files` 工具组
- 或用 Agent 按钮打开工具配置激活
- 或自行构造工具调用

## 注意事项

前后端的 Glob / Grep 有部分特殊规则：
- 忽略 `.` 开头的隐藏文件
- 读取工作区根目录的 `.ignore` 或 `.gitignore` (前者优先级更高) 并忽略匹配的路径
- 特殊规则：若一个忽略路径以 `/` 结尾，那么它会在 Glob 中显示，但省略子目录
- 特殊规则2（弃用）：后端会拒绝写入匹配的路径（无法防止通过命令或程序写入）

后端支持[ripgrep](https://github.com/BurntSushi/ripgrep) 你可以把它配置到环境变量中  
使用ripgrep的好处：**快**  
使用ripgrep的坏处：
- 浪费资源：每次调用都搜索整个路径，无法因文件数量足够而 early exit
- 兼容性差：不支持【省略子目录】规则，正则语法也和 JS 有所不同

## 安全

**命令执行没有沙盒**。如果允许，它可以在服务器上执行任意命令。  
不过，它只在[专用文件服务](./build.md#部署)中开启。

- 你应该使用 Docker 等容器技术隔离环境
- 或审查模型的命令执行请求（默认需要确认每一条命令）
- 好消息：自动沙箱模块正在开发中！

# 完全编辑模式

[设计理念](./philosophy.md#完全编辑模式)

### 如何使用

在消息上点击编辑按钮，即可修改对应内容。后续对话将基于修改后的内容继续。  
保存按钮的右侧是“追加工具调用”和“插入思考内容”按钮。  
每个工具调用通过点击展开，在修改后需要点击它们的保存按钮。  
如果 Schema 验证和点击按钮搞得你很烦躁，你甚至可以通过 `设置 > 数据管理 > 编辑当前对话的原始数据` 编辑 (数据无价，小心使用)
