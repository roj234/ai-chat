# ACL 规范

每行:
```regex
^[!]?[+-][rwl]+ <pattern>$
```
`#` 可作为整行注释

## 规则匹配语义（按优先级从低到高排序）
| 规则 | 匹配范围 |
|---|---|
| `*` | 全部 |
| `*.ext` | 任意路径 basename 扩展名 | ✓ 全局 |
| `name` | 任意路径 basename |
| `name/` | 路径中任意位置的段 |
| `/test/` | 前缀子树 |
| `/test/*.jpg` | 前缀扩展名 | ✓ |
| `/test/a.jpg` | 精确路径 | ✓ |

注意事项：
- pattern 字面匹配（无 glob，`se*.txt` 不通配）；
- 大小写不敏感；
- pattern 取"行剩余全部"（支持含空格文件名：`-r my file.txt`）；
- `*` 规则默认值为 +rwl；
- `!` 不是取反 (见下)
- `/` 只管能否列出根目录（唯一 `*` 无法表达的部分，`-l *` 是禁止列任何目录）

## 优先级
- `!` 大于非 `!`
- 都带 `!` 按特异性排序
- 特异性层：精确文件(7) > 前缀扩展(6) > 前缀(5) > 路径段(4) > 文件名(3) > 扩展名(2) > 默认(1)

## `l` 权限与列目录能力
1. `l` 的语义 = "在 r 基础上允许出现在列表里"。
   想隐藏结构须拒 l；想保护内容须拒 r；想保护完整性须拒 w——三者独立。
2. 直接列目录（Glob/Grep设置path/readdir）同时需要 **rl**
3. 递归 Glob：静默跳过被拒子树
4. Glob 时的条目可见性（出现在列表中）：
    - 文件：需要 r **和** l（缺任一即隐藏）
    - 目录：l 被拒→整个消失；有 l 无 r →显示但标 `(descents skipped)`
5. `l` 被拒的目录：文件操作全部照常作用于其中文件，仅仅是无法列举

## 用途

### 项目根的 `.acl` 文件
由于可能把自己锁在门外，所以暂不开放

### 子代理的 ACL 定义
子代理定义文件可以指定一个 ACL 文件。生效直到重启软件。
如果加载时就出现语法错误，应用回落规则：
```
-rwl *
+rl /
+rl /*
+rw /.acl
```
如果 ACL 文件不存在或为空，则没有限制
